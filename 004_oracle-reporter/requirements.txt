# Build backend: plain requirements.txt
#
# requirements.txt is the simplest Python dependency format.
# No build system, no lockfile, no virtual env management.
# Still widely used for:
#   - Simple scripts and one-off tools
#   - Teams unfamiliar with pyproject.toml tooling
#   - Projects where the CI environment already pins all deps
#
# Limitation: no dependency groups (dev vs prod).
# Workaround: separate requirements-dev.txt for test/lint dependencies.
#
# Migration path: `pip install pip-tools`, then `pip-compile requirements.in`
# generates a fully pinned requirements.txt from a loose requirements.in file.
